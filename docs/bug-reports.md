# Баг-репорты (Дефекты и несоответствия REST API)

### BUG-01: Отсутствие серверной валидации обязательных полей при создании поста (POST /posts)
* **Severity:** Major
* **Priority:** Medium
* **Окружение:** Production (`https://jsonplaceholder.typicode.com`), клиент Bruno / Postman

**Описание:**
При отправке `POST`-запроса на эндпоинт `/posts` с пустым JSON-объектом `{}` (без обязательных полей `title`, `body`, `userId`) сервер принимает запрос и возвращает статус успешного создания ресурса вместо ошибки валидации.

**Шаги воспроизведения:**
1. Выбрать метод `POST` и эндпоинт `https://jsonplaceholder.typicode.com/posts`.
2. Указать заголовок `Content-Type: application/json`.
3. Передать в тело запроса (`Body`) пустой объект `{}`.
4. Отправить запрос.

**Фактический результат:**
Сервер возвращает статус `201 Created` и тело ответа `{"id": 101}`.

**Ожидаемый результат:**
Сервер отклоняет запрос, возвращает статус `400 Bad Request` и JSON с описанием ошибок валидации (отсутствие обязательных полей `title`, `body`, `userId`).

**Примечание:** Воспроизводится в рамках логики mock-сервера JSONPlaceholder, однако для production-окружения является дефектом целостности данных.

### BUG-02: Сервер возвращает 500 Internal Server Error при попытке полного обновления несуществующего поста (PUT /posts/:id)
* **Severity:** Critical
* **Priority:** High
* **Окружение:** Production (`https://jsonplaceholder.typicode.com`), клиент Bruno / Postman

**Описание:**
При попытке выполнить полное обновление (`PUT`) ресурса по несуществующему идентификатору (`id = 676767`) сервер не обрабатывает отсутствие записи корректно и падает с внутренней ошибкой сервера (`500`).

**Шаги воспроизведения:**
1. Выбрать метод `PUT` и эндпоинт `https://jsonplaceholder.typicode.com/posts/676767`.
2. Передать в тело запроса (`Body` $\rightarrow$ `JSON`) валидный объект:
   ```json
   {
     "id": 676767,
     "title": "Updated Title",
     "body": "Updated Body",
     "userId": 1
   }
