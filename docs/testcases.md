# Тест-кейсы: Тестирование REST API JSONPlaceholder

### TC-01: Создание нового поста с валидными данными (`Create_Post`)
* **Приоритет:** High
* **Тип теста:** Позитивный / Функциональный
* **Предусловия:** API-сервис `https://jsonplaceholder.typicode.com` доступен.
* **Шаги воспроизведения:**
  1. Выбрать HTTP-метод `POST` и указать URL `{{baseUrl}}/posts`[cite: 1].
  2. Убедиться, что передаётся заголовок `Content-Type: application/json`.
  3. Передать в тело запроса (`Body` $\rightarrow$ `raw` $\rightarrow$ `JSON`) валидный объект:
     ```json
     {
       "title": "QA Internship Test",
       "body": "Testing POST endpoint via Bruno",
       "userId": 1
     }
     ```
    [cite: 1]
  4. Отправить запрос.
* **Ожидаемый результат:**
  * Код состояния HTTP: `201 Created`[cite: 1].
  * В ответе возвращается JSON-объект со всеми переданными полями (`title`, `body`, `userId`)[cite: 1].
  * Сервер присваивает новой записи идентификатор `id: 101`[cite: 1].

### TC-02: Частичное обновление заголовка поста (`Patch_Post_Title`)
* **Приоритет:** High
* **Тип теста:** Позитивный / Функциональный
* **Предусловия:** В базе данных существует пост с `id = 1`.
* **Шаги воспроизведения:**
  1. Выбрать HTTP-метод `PATCH` и указать URL `{{baseUrl}}/posts/:id`[cite: 1].
  2. В Path-переменных задать `id = 1`[cite: 1].
  3. Передать в тело запроса (`Body` $\rightarrow$ `JSON`) только обновляемое поле:
     ```json
     {
       "title": "Patched Title Only"
     }
     ```
    [cite: 1]
  4. Отправить запрос.
* **Ожидаемый результат:**
  * Код состояния HTTP: `200 OK`[cite: 1].
  * Поле `title` в ответе равно `"Patched Title Only"`[cite: 1].
  * Поля `id` (`1`), `userId` (`1`) и `body` (непустая строка) остались без изменений[cite: 1].

### TC-03: Фильтрация комментариев по идентификатору поста (`Filter_Comments_By_PostId`)
* **Приоритет:** Medium
* **Тип теста:** Позитивный / Функциональный
* **Предусловия:** В системе существуют комментарии, привязанные к посту с `id = 1`.
* **Шаги воспроизведения:**
  1. Выбрать HTTP-метод `GET` и указать URL `{{baseUrl}}/comments`[cite: 1].
  2. Добавить Query-параметр `postId` со значением `1`[cite: 1].
  3. Отправить запрос.
* **Ожидаемый результат:**
  * Код состояния HTTP: `200 OK`.
  * Тело ответа представляет собой непустой JSON-массив.
  * У каждого объекта в массиве значение ключа `"postId"` строго равно `1`, а также присутствуют поля `id`, `name`, `email`, `body`.

### TC-04: Запрос поста по несуществующему ID (`Get_Post_Not_Found`)
* **Приоритет:** Medium
* **Тип теста:** Негативный
* **Предусловия:** В базе данных отсутствует запись с `id = 676767`[cite: 1].
* **Шаги воспроизведения:**
  1. Выбрать HTTP-метод `GET` и указать URL `{{baseUrl}}/posts/:FakeId`[cite: 1].
  2. В Path-переменных задать `FakeId = 676767`[cite: 1].
  3. Отправить запрос.
* **Ожидаемый результат:**
  * Код состояния HTTP: `404 Not Found`[cite: 1].
  * Тело ответа содержит пустой JSON-объект `{}`[cite: 1].
